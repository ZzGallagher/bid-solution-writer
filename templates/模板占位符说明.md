# 模板占位符说明

本文档用于说明 `投标方案模板.docx` 中各类占位符的含义、命名规则和处理方式。模板中的占位符应使用统一格式，便于 Codex 或后续自动化流程识别、替换、生成和检查。

## 1. 占位符总体规则

占位符统一使用中文全角方括号：

```text
【类型:名称】
```

示例：

```text
【COPY:项目名称】
【GEN:总体架构设计】
【CONFIRM:投标人名称】
```

占位符由两部分组成：

- `类型`：说明该位置内容的处理方式。
- `名称`：说明该位置需要填充的具体内容。

推荐类型包括：

| 类型 | 含义 | 处理方式 |
|---|---|---|
| `COPY` | 直接复制、摘录或整理来源材料中的事实性内容 | 从招标文件、商务要求、评分表或用户资料中提取，不进行主观扩写 |
| `GEN` | 需要生成的方案正文、技术设计、响应说明、图表内容 | 根据招标要求、评分表、模板上下文和生成规则撰写 |
| `CONFIRM` | 需要人工确认的信息 | 不编造，保留占位符并在过程记录中提示用户补充 |
| `OPTIONAL` | 可选内容 | 有依据则生成或填充，无依据则保留或删除，需在记录中说明 |
| `REVIEW` | 需要重点复核的内容 | 可生成初稿，但必须在记录中标记为需人工复核 |

## 2. COPY 类占位符

`COPY` 表示该内容应直接来自已有资料，通常用于招标文件、商务条款、评分项、项目名称、采购人名称等事实性内容。

格式：

```text
【COPY:内容名称】
```

常用示例：

```text
【COPY:项目名称】
【COPY:招标人名称】
【COPY:采购编号】
【COPY:技术要求-总体要求】
【COPY:技术要求-用户管理】
【COPY:商务要求-服务期限】
【COPY:商务要求-付款方式】
【COPY:评分项-技术架构】
【COPY:评分项-功能完整性】
```

处理要求：

- 优先从 `input/技术要求.docx`、`input/商务要求.docx`、`input/技术评分表.docx` 中提取。
- 能原文引用的，尽量保持原文。
- 如原文过长，可做摘录或分条整理，但不得改变原意。
- 找不到明确来源时，不得编造，应保留占位符并记录在 `records/missing-source.md` 中。

推荐用途：

- 招标项目基础信息。
- 招标文件原始技术要求。
- 商务要求原文。
- 评分表评分项、分值、评分标准。
- 需要在方案中逐条响应的原始条款。

## 3. GEN 类占位符

`GEN` 表示该内容需要根据招标资料和生成规则撰写，是方案正文的主要生成区域。

格式：

```text
【GEN:内容名称】
```

常用示例：

```text
【GEN:总体架构设计】
【GEN:总体架构图】
【GEN:应用架构设计】
【GEN:数据架构设计】
【GEN:安全架构设计】
【GEN:部署架构设计】
【GEN:运维保障设计】
【GEN:功能设计-用户管理】
【GEN:功能设计-权限管理】
【GEN:功能设计-数据统计分析】
【GEN:流程图-用户管理】
【GEN:流程图-数据统计分析】
【GEN:商务响应-服务期限】
【GEN:评分响应强化-技术架构】
```

处理要求：

- 必须以招标文件、商务要求、评分表和模板章节上下文为依据。
- 不得编造具体厂商、型号、金额、人员姓名、证书编号、项目案例等事实信息。
- 对于技术功能设计，应逐项回应招标技术要求。
- 对于评分相关内容，应主动覆盖评分关键词和高分表达。
- 涉及 Mermaid 图的内容，应同时输出：
  - Mermaid 源码文件，保存到 `output/records/`。
  - 渲染后的图片文件，保存到 `output/records/`。
  - 插入到最终 `.docx` 文档中的图片。

推荐用途：

- 软件架构设计。
- 软件功能设计。
- 技术实现方案。
- 业务流程说明。
- Mermaid 架构图、流程图、部署图。
- 技术评分点强化说明。
- 商务条款响应说明。

## 4. CONFIRM 类占位符

`CONFIRM` 表示该内容必须由用户或投标单位确认，Codex 不应自行生成确定值。

格式：

```text
【CONFIRM:内容名称】
```

常用示例：

```text
【CONFIRM:投标人名称】
【CONFIRM:联合体成员】
【CONFIRM:项目经理】
【CONFIRM:项目团队成员】
【CONFIRM:服务期限承诺】
【CONFIRM:交付地点】
【CONFIRM:报价信息】
【CONFIRM:公司资质】
【CONFIRM:类似项目业绩】
【CONFIRM:产品名称】
【CONFIRM:部署环境】
```

处理要求：

- 如用户未提供明确资料，应保留占位符。
- 在 `output/records/人工确认清单.md` 中列出所有未确认项。
- 可以根据上下文给出填写建议，但不得替用户填写事实性结论。

推荐用途：

- 投标人自身信息。
- 人员、资质、证书、案例。
- 报价、工期、服务承诺。
- 产品品牌、已有系统名称、部署环境。
- 任何可能影响投标真实性和合规性的内容。

## 5. OPTIONAL 类占位符

`OPTIONAL` 表示该内容可根据项目情况决定是否保留。

格式：

```text
【OPTIONAL:内容名称】
```

常用示例：

```text
【OPTIONAL:国产化适配说明】
【OPTIONAL:信创环境支持说明】
【OPTIONAL:移动端设计】
【OPTIONAL:第三方系统对接】
【OPTIONAL:数据迁移方案】
```

处理要求：

- 如果招标文件或评分表中明确要求，应转为必须生成内容。
- 如果没有依据但适合作为加分内容，可以生成稳健描述，并在记录中说明来源为“方案增强建议”。
- 如果与项目无关，应从生成稿中删除或保留为待确认项。

## 6. REVIEW 类占位符

`REVIEW` 表示可以生成初稿，但必须人工复核。

格式：

```text
【REVIEW:内容名称】
```

常用示例：

```text
【REVIEW:技术偏离表】
【REVIEW:商务偏离表】
【REVIEW:服务承诺】
【REVIEW:实施周期安排】
【REVIEW:验收标准】
```

处理要求：

- 可根据招标文件生成初稿。
- 必须在 `output/records/复核清单.md` 中列出。
- 涉及承诺、偏离、验收、工期、付款等内容时，必须提示用户最终确认。

## 8. 命名建议

为便于自动匹配，建议占位符名称遵循以下规则：

- 同一类要求使用统一前缀，如 `技术要求-`、`商务要求-`、`评分项-`。
- 功能设计和流程图使用同一功能名称，例如：

```text
【GEN:功能设计-用户管理】
【GEN:流程图-用户管理】
```

- 不建议使用过于模糊的名称，例如：

```text
【GEN:这里写一下】
【COPY:相关内容】
【CONFIRM:信息】
```

- 推荐使用清晰、稳定、可追踪的名称，例如：

```text
【GEN:功能设计-数据查询统计】
【COPY:技术要求-数据查询统计】
【GEN:评分响应强化-数据分析能力】
```

## 9. 输出记录要求

每次生成投标方案时，应在 `output/records/` 下保留过程记录：

```text
output/records/
  requirements-matrix.md
  placeholder-fill-log.md
  missing-source.md
  人工确认清单.md
  复核清单.md
  architecture.mmd
  architecture.png
  function-001.mmd
  function-001.png
```

其中：

- `requirements-matrix.md`：招标要求、评分项与方案章节的映射关系。
- `placeholder-fill-log.md`：每个占位符的处理结果。
- `missing-source.md`：未找到来源的 COPY 占位符。
- `人工确认清单.md`：所有 CONFIRM 占位符。
- `复核清单.md`：所有 REVIEW 占位符。
- `.mmd` 文件：Mermaid 源码。
- `.png` 文件：Mermaid 渲染图片。

## 10. 当前模板占位符清单

当前 `templates/投标方案模板.docx` 已按本说明完成标准化，模板中的占位符分为以下几组。

### 10.1 COPY 占位符

```text
【COPY:项目名称】
【COPY:技术要求-功能要求】
【COPY:技术要求-性能要求】
【COPY:技术要求-通用质量特性要求】
```

处理要求：

- `【COPY:项目名称】` 从招标文件、项目资料或用户确认信息中提取。
- 技术要求类占位符从 `input/技术要求.docx` 中提取或归纳，不得改变原意。
- 如技术要求文件未明确区分功能、性能、通用质量特性，应先生成 `requirements-matrix.md`，再按语义拆分填入。

### 10.2 GEN 占位符

```text
【GEN:编写目的】
【GEN:建设内容】
【GEN:总体架构设计】
【GEN:总体架构图】
【GEN:架构图说明】
【GEN:设计原则】
【GEN:部署架构设计】
【GEN:功能设计总述】
【GEN:功能设计章节】
【GEN:性能设计章节】
【GEN:数据库设计总述】
【GEN:数据库架构设计】
【GEN:核心业务数据设计】
【GEN:数据库表设计】
【GEN:通用质量特性设计总述】
【GEN:可靠性设计】
【GEN:维修性设计】
【GEN:保障性设计】
【GEN:测试性设计】
【GEN:安全性设计】
【GEN:环境适应性设计】
【GEN:关键技术】
【GEN:质量控制总述】
【GEN:风险评估与控制】
【GEN:质量保证措施】
【GEN:培训方案】
```

处理要求：

- `【GEN:功能设计章节】` 是动态章节入口，应根据技术要求中的功能点自动扩展为多个功能小节。
- 每个功能小节应包含功能说明、实现方式、业务流程、数据处理、权限安全、异常处理、招标响应说明，并生成对应 Mermaid 流程图。
- `【GEN:总体架构图】` 应生成 Mermaid 源码、渲染图片，并将图片插入 Word 模板对应位置。
- 数据库、性能、六性、质量、培训等内容必须结合招标要求和评分项生成，不得直接复用其他项目的专有描述。

### 10.3 CONFIRM 占位符

```text
【CONFIRM:项目团队人员说明】
【CONFIRM:项目团队-职务分工】
【CONFIRM:项目团队-姓名】
【CONFIRM:项目团队-职称】
【CONFIRM:项目团队-专业】
【CONFIRM:项目团队-从业资格】
【CONFIRM:项目团队-相关工作年限】
【CONFIRM:质量保证期承诺】
【CONFIRM:售后服务响应承诺】
```

处理要求：

- 项目团队表中的 `CONFIRM` 占位符必须由用户提供真实人员信息后再替换。
- 质量保证期、售后响应时限、到场时限、故障恢复时限等均属于承诺类内容，未获得用户确认前不得自行填写。
- 未确认项应写入 `output/records/人工确认清单.md`。

### 10.4 REVIEW 占位符

```text
【REVIEW:质量体系与资质响应说明】
【REVIEW:服务质量保障措施】
【REVIEW:项目进度计划】
【REVIEW:成果交付及验收】
【REVIEW:交付物清单】
【REVIEW:应急支援保障承诺】
【REVIEW:定期跟踪服务承诺】
```

处理要求：

- `REVIEW` 内容可以生成初稿，但必须提示用户复核。
- 涉及资质、服务承诺、进度、交付物、验收、应急保障的内容，不得生成不可核实的强承诺。
- 需复核项应写入 `output/records/复核清单.md`。

## 11. 本次模板优化说明

当前模板已做以下优化：

- 将长句式、说明式 `GEN` 占位符改为短名称，详细生成要求转移到 `生成规则.md`。
- 将示例功能正文从模板正文中移除，避免后续生成时误复用其他项目内容。
- 将固定服务承诺、质量保证期、响应时限等高风险内容改为 `CONFIRM` 或 `REVIEW`。
- 保留模板原有章节骨架、封面表格、参考依据表、交付物表和项目团队表。
- 在项目团队表首行加入 `CONFIRM` 字段，便于后续自动识别需要人工补充的信息。
